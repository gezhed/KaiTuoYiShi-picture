# 文生图教程（ComfyUI）

本文件夹放一份可直接用的 ComfyUI 文生图工作流，以及在本应用里接入它的步骤。
更完整的排错清单见 [`docs/文生图-实机验证清单.md`](../docs/文生图-实机验证清单.md)。
可以优先查看智绘姬的官方教程，比这个教程详细很多，原贴：https://discord.com/channels/1134557553011998840/1215675312721887272

## 文件

| 文件 | 说明 |
|---|---|
| `工作流.json` | **用这个。** 已经写成本应用认识的 `%…%` 占位符，并内置 4 个角色 LoRA 槽位；整段粘贴进「工作流」页即可。 |
| `llm预设.json` | 社区作者的「正文 → 插图提示词」LLM 预设，在「文生图 → LLM 预设」里导入。 |
| `角色AI预设-人物生成.json` | **一键生成角色特征**的提示词预设（破甲对话 + `<人物>`/`<服装>` 格式规格）。见下面第五节。 |

> 这份工作流包含：`%prompt%` / `%negative_prompt%`（提示词必须的）、`%MODEL_NAME%`、
> `%width%` / `%height%`、`%seed%` / `%steps%` / `%cfg_scale%` / `%sampler_name%` / `%scheduler%`，
> 以及 4 个 `LoraLoader` 槽位（`%lora_name_1%`…，角色绑的 LoRA 按出场顺序填；没填的槽提交前自动跳过）。

## 一、先启动 ComfyUI

```bash
python main.py --enable-cors-header
```

不加 `--enable-cors-header`，浏览器直连会被挡，表现为`Failed to fetch`。

在 ComfyUI 里确认 checkpoint 已放进 `models/checkpoints/`，并记住文件名。

## 二、导出工作流

在本文件夹里已经给了一份 API 格式的 JSON，可以直接用。
若要换成自己的工作流：ComfyUI 里点 **Save (API Format)** 导出，
**不要用默认的 Save**——那是 UI 格式，本应用会拒绝。

## 三、在本应用里配置

1. 设置 → 文生图 → **总览**：渠道选 `ComfyUI`，打开「启用文生图」。
2. **ComfyUI** 页：地址填 `http://127.0.0.1:8188` → 点「测试连接」→
   成功后点「读取模型列表」，选一个 checkpoint。
3. **工作流** 页：粘贴 `工作流.json` 的全部内容。
4. 设置 → 文生图 → **提示词**页点「自检」，红灯全部消掉。

## 四、占位符用法

工作流里想被替换的位置，值写成**带引号的字符串**：

```json
"seed": "%seed%"
```

- 正确：`"seed": "%seed%"` —— 替换后变成裸数字 `"seed": 12345`
- 错误：`"seed": %seed%` —— JSON 本身就不合法，粘贴时就会被拒

常用的几个：

| 占位符 | 含义 |
|---|---|
| `%prompt%` | 正面提示词 |
| `%negative_prompt%` | 负面提示词 |
| `%MODEL_NAME%` | 模型文件名（`ckpt_name`） |
| `%width%` / `%height%` | 宽 / 高 |
| `%seed%` | 种子 |
| `%steps%` | 步数 |
| `%cfg_scale%` | CFG |
| `%sampler_name%` | 采样器 |
| `%scheduler%` | 调度器 |
| `%comfyuicankaotupian%` | 参考图文件名 |

容易写错的：负面词是 `%negative_prompt%`（不是 `%negative%`）、
模型是 `%MODEL_NAME%`（大写）、CFG 是 `%cfg_scale%`（不是 `%cfg%`）。
名字写错**不会报错**，只会留一个没被替换的 `%…%` 在提交体里、出图与正文无关。

## 五、出图

视觉资产 → **手动出图**，填一段提示词点生成，先确认单张能出。
通了再回到「总览」打开「启用正文配图」，并配好「提示词」页的**转化器**（一个可用的 LLM 接口），
这样回复就会自动配图。

## 六、出问题时

| 现象 | 先查 |
|---|---|
| `Failed to fetch` | ComfyUI 有没有加 `--enable-cors-header` |
| 提示工作流是 UI 格式 | 用 Save (API Format) 重新导出 |
| `Value not in list` | 工作流里模型名写死了；换成 `%MODEL_NAME%`，并确认「读取模型列表」里选的和 ComfyUI 里实际存在的模型一致 |
| 出图但提示词没生效 | 提示词位置是不是还在用 `__PROMPT__`；换成 `%prompt%` |
| 提交体里残留 `%…%` | 占位符名拼错了，对照上面表格逐字核对 |
| 一直排队不返回 | ComfyUI 队列是否卡住；默认超时 1800 秒 |

工作流只负责「怎么画」，采样参数、尺寸、模型这些**能设就别写死**，
写成占位符才能在界面上调。

## 五、一键生成角色特征：导入「人物生成」预设

「文生图 → 角色管理 → 生成」页让模型按格式产出 14 个部位字段。

**预设默认是空白的**（不再内置任何提示词），要自己去导入。点「角色 AI 设置」里的
**「导入预设 JSON」**，选本文件夹的 `角色AI预设-人物生成.json` 即可。它包含：

| 消息 | 作用 |
|---|---|
| 初始化（破甲对话） | 把模型带进「边界内可以写得具体」的状态。没有它，模型面对 NSFW 字段最省事的做法就是回一句拒绝 —— 也就是「经常空回」。 |
| 故事框架 开 / 合 | 破甲流程里的包裹标记。 |
| 增强定义 / user人设 | 破甲对话的收束轮。 |
| 角色设计 | `<人物>` 区块的 14 个字段格式。 |
| 服装风格 | `<服装>` 区块的格式。 |
| 讨论模式 | 要求先输出 `<talk>` 讨论。**默认停用**：本应用是单次调用，开着容易把输出额度耗在讨论上而给不出 `<人物>` 块。 |

导入后可以逐条改、启停、上下移，也可以随时「导出当前预设」备份或分享给别人。
预设为空时界面会提示——**没有格式约束时，一键生成多半拿不到 `<人物>` 块**。

## 六、按角色固定形象：LoRA 与参考图

「角色管理 → 角色卡」新增 **LoRA** 一栏（先在「文生图 → ComfyUI → 连接」点
**读取模型列表**，下拉里就有 LoRA 文件名）。绑定后**只有该角色出场时**才生效。

**ComfyUI**：本教程的 `工作流.json` **已经内置这 4 个槽位**（节点 20–23，
`"lora_name": "%lora_name_N%"`、`"strength_model"` 与 `"strength_clip"` 用 `"%lora_weight_N%"`），
直接粘贴就能用。**没填的槽会自动跳过**（下游接到上游），所以不用为空槽另做工作流。
若你要自己改工作流：串 4 个 `LoraLoader`，把 KSampler 的 `model`、
CLIPTextEncode 的 `clip` 指到最后一环即可 —— 完整示例与排错见
[`docs/文生图-实机验证清单.md` 第 6.7 节](../docs/文生图-实机验证清单.md)。

**SD / A1111**：不用改工作流，把 `{lora}` 写进「注入模板 → 角色列表」即可。

**参考图（不想用 LoRA 时的另一条路）**：总览打开「参考图上传」，给角色卡放一张图
（用途标「参考」），工作流里用 `%comfyuicankaotupian%`（IPAdapter / LoadImage）——
这条链路按角色自动挑图，对「部分角色不像」往往比 LoRA 更省事。
