## 一、先看这五条（能省半小时）

1. **这是纯前端 SPA，没有后端。** `pnpm dev` 起的 Vite 中间件（`vite.config.ts`）提供了存档 / 局域网 / 实时同步 / AI 中转的全部服务端能力；**部署到 Cloudflare Pages 之后这些 `/api/*` 都不存在**，只剩 `functions/api/*` 那几个具名代理。遇到「本地能用、部署后失效」，先怀疑这一条。
2. **设置是草稿语义**：改的是内存，页面底部的「保存」才落盘。任何「改了没生效」先分清是**没按保存**，还是**归一化丢了字段**。
3. **配置归一化只有两个入口**：`utils/gameSettingsHydration.ts:106` 的 `归一化游戏设置`（落盘前）和 `:132` 的 `hydratePersistedGameSettings`（启动读回）。「保存了、重启就变回去」先查这里。
4. **`pnpm lint`（`eslint .`）全仓本来就是红的**，别拿它当门槛，只查你改的文件。
5. **全量测试约 25 秒**；改一处优先 `npx vitest run tests/<相关目录>`，不要每次都全量。

## 三、怎么提交（重要）

`github.com:443` 的 **git 传输被阻断**：`git ls-remote` 偶尔能通，`clone` / `push` 基本失败。
走 GitHub REST API：`scripts/push-via-api.mjs`（blob → tree → commit → 更新 ref），清单一行一个仓库内路径。

```bash
node scripts/push-via-api.mjs --repo gezhed/KaiTuoYiShi-picture --branch main \
  --files /tmp/清单.txt --message-file /tmp/提交说明.txt --base-tree
```

局部提交**必须**带 `--base-tree`，否则新树会把仓库其余文件顶掉；整份替换才省略它。

## 六、不变量与陷阱

1. **草稿语义**：文生图、记忆、新闻等子系统页都是「改内存 → 页面保存才落盘」。别在面板里直接写 `saveSetting`。
2. **归一化两个入口**（见第一条）。新增设置字段时三处要一起改：类型 → `创建默认*` → `归一化*`。
3. `文生图词组转化器API` 这个**字面量键名不能改**，它已经写进用户导出的配置包。
4. `/api/ai/*`、`/api/live/*`、存档接口**只在 dev / preview 存在**；静态托管下 CORS 兜底会静默失效（探测到没有端点后不再重试）。
5. **中文标识符 + 中文界面文案几乎一一对应** → 用界面上那句话 `grep`，定位最快。这是这个仓库最大的便利，别忽略。
6. 大文件整读很贵，按行读：`NewGame/wizard/steps.tsx` 1663、`models/npc.ts` 1517、`data/builtinPromptModules.ts` 1316、`models/genSystem.ts` 1294、`hooks/useGame.ts` 1294、`ComfyUISettingsConsole.tsx` 1145、`PromptModulesTab.tsx` 1119、`App.tsx` 1099。
7. **`SettingsModal` 有两个实例**（`App.tsx:666` 游戏内、`:799` 首页），加 props 要同步两处。
8. 配置包 `includeApiKeys=false` 时会把 Key 清空，安全包不能用来迁移密钥。
9. 用例之间 `localStorage` 会串（例如页签记忆的 `kty.settingsTab`），相关用例要自己清理。
