# 文生图移植：实机验证清单

> 这份清单只讲**怎么验证**与**失败时看哪里**。移植范围与上游对应关系见
> `chatu8-comfyui-spec.md`、`chatu8-llm-spec.md`、`chatu8-character-spec.md`
> 与 `third_party/st-chatu8/NOTICE.md`。

## 当前状态（务必先读）

代码侧：`tsc` 0 错误、112 个测试文件 / 1147 项测试全过、生产构建成功。

**但没有任何一个渠道经过实机验证。** 所有验证都是单元测试与纯函数层的，
网络请求、服务端对载荷的接受程度、CORS、实际出图质量都未经验证。

因此下面的顺序是**从最可能通到最可能出问题**，请按序推进，不要一次全配。

---

## 第 0 步：不联网的自检（先做这个）

设置 → **文生图 → 提示词**页有两块面板，都**不发请求、不消耗额度**：

| 面板 | 作用 |
|---|---|
| **提示词预览** | 把「剥标记 → 剥尺寸 → 角色替换 → 替换规则 → 组装正负词」五步摊开 |
| **自检** | 按当前渠道检查配置，区分「配置错误」与「运行时错误」 |

自检会直接告诉你当前缺什么。**红灯（✕）不解决，出图一定失败**；黄灯（!）是可以出图但值得留意。

这一步能挡掉的常见问题：工作流存成了 UI 格式、没填地址、没填 Token、
工作流里没有提示词占位符、开了参考图但工作流没有参考图占位符、Vibe 文件与模型不匹配。

## 第 1 步：ComfyUI（建议先测这个）

### 前置

1. ComfyUI 启动时**加上 CORS 头**：
   ```
   python main.py --enable-cors-header
   ```
   不加的话浏览器直连会被挡，表现为「测试连接失败」或 `Failed to fetch`。
2. 在 ComfyUI 里搭好工作流，用 **Save (API Format)** 导出
   （不是默认的 Save，默认导出的是 UI 格式，本应用会明确拒绝并提示）。

### 配置

设置 → 文生图 → **总览**：渠道选 ComfyUI，打开「启用文生图」。

**ComfyUI** 页：地址填 `http://127.0.0.1:8188` → 点「测试连接」→
成功后点「读取模型列表」，选择 checkpoint。

**工作流** 页：粘贴 API 格式 JSON。占位符要写成**带引号的字符串**，例如：

```json
"seed": "%seed%"
```

- 正确：`"seed": "%seed%"`（会被替换成数字）
- 错误：`"seed": %seed%`（JSON 本身就不合法）

推荐占位符。**名字必须逐字照抄**——写错不会报错，只会留一个没被替换的
`%…%` 在提交体里（自检会对不认识的占位符给出黄灯）：

| 占位符 | 含义 | 类型 |
|---|---|---|
| `%prompt%` | 正面提示词 | 字符串 |
| `%negative_prompt%` | 负面提示词 | 字符串 |
| `%width%` / `%height%` | 宽 / 高 | 数字 |
| `%seed%` | 种子 | 数字 |
| `%steps%` | 步数 | 数字 |
| `%cfg_scale%` | CFG | 数字 |
| `%sampler_name%` | 采样器 | 字符串 |
| `%scheduler%` | 调度器 | 字符串 |
| `%MODEL_NAME%` | 模型（ckpt_name） | 字符串 |
| `%vae%` / `%clip%` | VAE / CLIP | 字符串 |
| `%comfyuicankaotupian%` | 参考图文件名 | 字符串 |
| `%c_quanzhong%` / `%c_idquanzhong%` | IPA 权重 / FaceID 权重 | 数字 |
| `%c_xijie%` / `%c_fenwei%` | 细节强度 / 氛围强度 | 数字 |
| `%ipa%` | IPA 类型 | 字符串 |

注意几个容易想当然写错的：负面词是 **`%negative_prompt%`**（不是 `%negative%`）、
模型是 **`%MODEL_NAME%`**（大写，不是 `%model%`）、采样器是 **`%sampler_name%`**
（不是 `%sampler%`）、CFG 是 **`%cfg_scale%`**（不是 `%cfg%`）。

重绘族（`%inpaint_image%`、`%inpaint_mask%`、`%inpaint_denoise%`、
`%inpaint_positive%`、`%inpaint_negative%`）也在表里。

### 出图

视觉资产 → **手动出图**：填一段提示词（或直接写 `image###1girl, solo###`），点生成。

### 失败时看哪里

| 现象 | 先查 |
|---|---|
| `Failed to fetch` | ComfyUI 有没有开 CORS |
| 提示工作流是 UI 格式 | 用 Save (API Format) 重新导出 |
| 报某个节点的参数非法 | 该占位符的值超范围，或占位符写在了非字符串位置 |
| 一直排队不返回 | ComfyUI 队列里有没有卡住的任务；超时默认 1800 秒 |
| 出图但提示词没生效 | 工作流里 `%prompt%` 是否接在 CLIPTextEncode 上 |
| 提交体里残留 `%…%` | 占位符名写错了；对照上面的表格逐字核对 |

### 自动化覆盖到什么程度

四个渠道都有**假服务端集成测试**，走真实分派与载荷构造，只把服务端换掉：

| 文件 | 覆盖 |
|---|---|
| `tests/ai/comfy-integration.test.ts` | 提交 → 轮询 → 取图；上行工作流的实际内容；参考图先上传再提交；同图不重复上传；提交被拒时报出服务端错误体 |
| `tests/ai/novelai-integration.test.ts` | zip 与裸图两种响应；字段族齐全；分角色与位置；Director Reference 六字段与强度归一化；Vibe 编码提取与模式互斥 |
| `tests/ai/sd-banana-integration.test.ts` | SD 端点与载荷类型、认证头、资源列表、高清修复与 ADetailer；Banana 端点推导、四种响应形态、`imagen*` 不发 size、参考图开关 |

所以「客户端把请求拼错了」「端点选错了」「开关没生效」这类问题**已被覆盖**。
**没被覆盖的是服务端的真实接受程度**：CORS 行为、服务端版本差异、
工作流本身节点接线是否正确、显存与模型是否匹配、以及**出图质量**。

## 第 2 步：NovelAI

### 配置

**NovelAI** 页：Token（持久化 Token，不是账号密码）→ 模型从下拉选。

### 分三个层次测，不要一次全开

1. **先只出图**：关掉参考组相关的一切，手动出图一张。
   验证 `params_version`、`skip_cfg_above_sigma`、尺寸这些基础字段被接受。
2. **再加参考图**：到「角色管理 → NovelAI 参考组」，模式选「角色参考（图片）」，
   **先只加 1 张图、强度 0.6**。参考图的载荷结构最复杂，出问题时先减到 1 张。
3. **最后试 Vibe**：模式切到「Vibe transfer」，上传 `.naiv4vibe`。
   上传时会**先按当前模型验证能否取出编码**，取不到会直接拒绝并说明原因。

### 失败时看哪里

| 现象 | 先查 |
|---|---|
| HTTP 401 | Token 是否有效、是否用了账号密码 |
| HTTP 400 且提到 v4_prompt | 模型与分角色载荷不匹配；换用下拉里的模型 |
| 参考图没生效 | 自检面板会明说「没有一个 Vibe 能用于当前模型」或参考图缺失 |
| 位置没生效 | 该角色「位置」是否设了；提示词里要有 `$角色名-…$` 才会被识别为分角色 |
| 第三方站点报 404 | 路径写法不一，客户端会依次试「地址 + /ai/generate-image」与裸地址，两个都失败才报错 |

## 第 3 步：SD WebUI（A1111 / Forge）

### 前置

WebUI 必须带 `--api` 启动，否则所有 `/sdapi/v1/*` 都 404。

### 配置

**SD WebUI** 页：地址 `http://127.0.0.1:7860` → 点「测试并读取模型列表」→
选模型、采样器、VAE（下拉内容来自服务端，比手填可靠）。

### 注意

**SD 渠道没有参考图机制，这是上游的行为，不是移植缺口。**
上游的 SD 路径只有 ADetailer 面部重绘；参考图是 ComfyUI 的 IP-Adapter 节点能力。
需要参考图请用 ComfyUI 或 NovelAI。自检面板也会这么提示。

## 第 4 步：Banana / Grok

**Banana / Grok** 页：地址、API Key、模型、尺寸。
设置页会**实时显示**当前会请求哪个端点，以及带参考图时会改请求哪个端点——
先核对这两个地址，再点生成。

配置界面里可以切「参考图发送形态」（multipart / JSON）。默认 multipart 是上游做法；
部分中转站只认 JSON 形式，切换即可。

**Banana 不支持负面提示词与种子。** 负向词不会发给服务端，生成参数里的种子记为「不适用」。

---

## 第 5 步：正文自动配图链路

前四步是单张出图。正文配图还多两个环节：**LLM 生成提示词** 与 **图片归档**。

打开「总览 → 启用正文配图」，并在「提示词」页配好**转化器**（一个可用的 LLM 接口）。

### 验证点

1. 发一条消息，看回复后是否自动出图。
2. **一张图**应插在正文对应行下方（按锚点匹配），不是全部堆在末尾。
3. 点单张图的「改提示词并重生」→ 只重生这一张。
4. 点「重生成提示词」→ **只换提示词、保留已出的图**。
5. 一条回复里多张图（模型输出多个 `<image>` 块）。

### 失败时看哪里

| 现象 | 先查 |
|---|---|
| 没有任何图 | 「提示词预览」先确认转化器能用；自检会提示转化器未启用 |
| 图全堆在末尾 | 锚点行匹配不到正文，属正常回退；检查提示词里的锚点行是否照抄了正文 |
| 插图和行对不上 | 锚点行相似度阈值（40）；正文里那一行是否被改动过 |
| 只出一张 | 模型输出里只有一个 `<image>` 块；「每轮上限」是否设成了 1 |

## 已知的、刻意保留的行为

这些看起来像 bug，其实是照搬上游。**不要顺手"修"**（测试里已固化）：

- `小学生` → `🏬生`：词汇替换的子串遮蔽
- 提示词里的尺寸 `WxH` **后跟逗号时不匹配**
- 全角归一化只处理 `,`，不处理 `;` 与 `:`
- 角色卡的 `fullBody*` 字段承载的是**下半身**，不是全身（界面文案已写「下半身」）
- 打开「参考强度归一化」时，**4.5 full/curated 反而交给 NAI 自己归一化**
- 角色参考的「保真度」**不上行**，发送的是 `1 - 强度`（界面上没有暴露该字段）
- Banana 的 `imagen*` 模型**不发 `size`**

## 上游没有的能力（不是缺口）

- SD 渠道的参考图（只有 ComfyUI 的 IP-Adapter 节点）
- 视频（本轮范围外，用户明确暂不需要）
