# 文生图移植：实机验证清单

> 这份清单只讲**怎么验证**与**失败时看哪里**。移植范围与上游对应关系见
> `chatu8-comfyui-spec.md`、`chatu8-llm-spec.md`、`chatu8-character-spec.md`
> 与 `third_party/st-chatu8/NOTICE.md`。

## 当前状态（务必先读）

代码侧：`tsc` 0 错误、146 个测试文件 / 1618 项测试全过、生产构建成功。

**但没有任何一个渠道经过实机验证。** 所有验证都是单元测试与纯函数层的，
网络请求、服务端对载荷的接受程度、CORS、实际出图质量都未经验证。
「角色管理 → 生成」的一键生成同样只有假模型调用的测试覆盖，
真实模型能不能稳定吐出 `<人物>` 格式尚未实机确认。

因此下面的顺序是**从最可能通到最可能出问题**，请按序推进，不要一次全配。

---

## 第 0 步：不联网的自检（先做这个）

设置 → **文生图 → 提示词**页有两块面板，都**不发请求、不消耗额度**：

| 面板 | 作用 |
|---|---|
| **提示词预览** | 把「剥标记 → 剥尺寸 → 角色替换 → 替换规则 → 组装正负词」五步摊开 |
| **自检** | 按当前渠道检查配置，区分「配置错误」与「运行时错误」 |

自检会直接告诉你当前缺什么。**红灯（✕）不解决，出图一定失败**；黄灯（!）是可以出图但值得留意。

这一步能挡掉的常见问题：工作流存成了 UI 格式、没填地址、没填 Token、
工作流里没有提示词占位符、开了参考图但工作流没有参考图占位符、Vibe 文件与模型不匹配。

## 第 1 步：ComfyUI（建议先测这个）

### 前置

1. ComfyUI 启动时**加上 CORS 头**：
   ```
   python main.py --enable-cors-header
   ```
   不加的话浏览器直连会被挡，表现为「测试连接失败」或 `Failed to fetch`。
2. 在 ComfyUI 里搭好工作流，用 **Save (API Format)** 导出
   （不是默认的 Save，默认导出的是 UI 格式，本应用会明确拒绝并提示）。

### 配置

设置 → 文生图 → **总览**：渠道选 ComfyUI，打开「启用文生图」。

**ComfyUI** 页：地址填 `http://127.0.0.1:8188` → 点「测试连接」→
成功后点「读取模型列表」，选择 checkpoint。

**工作流** 页：粘贴 API 格式 JSON。占位符要写成**带引号的字符串**，例如：

```json
"seed": "%seed%"
```

- 正确：`"seed": "%seed%"`（会被替换成数字）
- 错误：`"seed": %seed%`（JSON 本身就不合法）

推荐占位符。**名字必须逐字照抄**——写错不会报错，只会留一个没被替换的
`%…%` 在提交体里（自检会对不认识的占位符给出黄灯）：

| 占位符 | 含义 | 类型 |
|---|---|---|
| `%prompt%` | 正面提示词 | 字符串 |
| `%negative_prompt%` | 负面提示词 | 字符串 |
| `%width%` / `%height%` | 宽 / 高 | 数字 |
| `%seed%` | 种子 | 数字 |
| `%steps%` | 步数 | 数字 |
| `%cfg_scale%` | CFG | 数字 |
| `%sampler_name%` | 采样器 | 字符串 |
| `%scheduler%` | 调度器 | 字符串 |
| `%MODEL_NAME%` | 模型（ckpt_name） | 字符串 |
| `%vae%` / `%clip%` | VAE / CLIP | 字符串 |
| `%comfyuicankaotupian%` | 参考图文件名 | 字符串 |
| `%c_quanzhong%` / `%c_idquanzhong%` | IPA 权重 / FaceID 权重 | 数字 |
| `%c_xijie%` / `%c_fenwei%` | 细节强度 / 氛围强度 | 数字 |
| `%ipa%` | IPA 类型 | 字符串 |

注意几个容易想当然写错的：负面词是 **`%negative_prompt%`**（不是 `%negative%`）、
模型是 **`%MODEL_NAME%`**（大写，不是 `%model%`）、采样器是 **`%sampler_name%`**
（不是 `%sampler%`）、CFG 是 **`%cfg_scale%`**（不是 `%cfg%`）。

重绘族（`%inpaint_image%`、`%inpaint_mask%`、`%inpaint_denoise%`、
`%inpaint_positive%`、`%inpaint_negative%`）也在表里。

### 出图

视觉资产 → **手动出图**：填一段提示词（或直接写 `image###1girl, solo###`），点生成。

### 失败时看哪里

| 现象 | 先查 |
|---|---|
| `Failed to fetch` | ComfyUI 有没有开 CORS |
| 提示工作流是 UI 格式 | 用 Save (API Format) 重新导出 |
| 报某个节点的参数非法 | 该占位符的值超范围，或占位符写在了非字符串位置 |
| 一直排队不返回 | ComfyUI 队列里有没有卡住的任务；超时默认 1800 秒 |
| 出图但提示词没生效 | 工作流里 `%prompt%` 是否接在 CLIPTextEncode 上 |
| 提交体里残留 `%…%` | 占位符名写错了；对照上面的表格逐字核对 |

### 自动化覆盖到什么程度

四个渠道都有**假服务端集成测试**，走真实分派与载荷构造，只把服务端换掉：

| 文件 | 覆盖 |
|---|---|
| `tests/ai/comfy-integration.test.ts` | 提交 → 轮询 → 取图；上行工作流的实际内容；参考图先上传再提交；同图不重复上传；提交被拒时报出服务端错误体 |
| `tests/ai/novelai-integration.test.ts` | zip 与裸图两种响应；字段族齐全；分角色与位置；Director Reference 六字段与强度归一化；Vibe 编码提取与模式互斥 |
| `tests/ai/sd-banana-integration.test.ts` | SD 端点与载荷类型、认证头、资源列表、高清修复与 ADetailer；Banana 端点推导、四种响应形态、`imagen*` 不发 size、参考图开关 |

所以「客户端把请求拼错了」「端点选错了」「开关没生效」这类问题**已被覆盖**。
**没被覆盖的是服务端的真实接受程度**：CORS 行为、服务端版本差异、
工作流本身节点接线是否正确、显存与模型是否匹配、以及**出图质量**。

## 第 2 步：NovelAI

### 配置

**NovelAI** 页：Token（持久化 Token，不是账号密码）→ 模型从下拉选。

### 分三个层次测，不要一次全开

1. **先只出图**：关掉参考组相关的一切，手动出图一张。
   验证 `params_version`、`skip_cfg_above_sigma`、尺寸这些基础字段被接受。
2. **再加参考图**：到「角色管理 → NovelAI 参考组」，模式选「角色参考（图片）」，
   **先只加 1 张图、强度 0.6**。参考图的载荷结构最复杂，出问题时先减到 1 张。
3. **最后试 Vibe**：模式切到「Vibe transfer」，上传 `.naiv4vibe`。
   上传时会**先按当前模型验证能否取出编码**，取不到会直接拒绝并说明原因。

### 失败时看哪里

| 现象 | 先查 |
|---|---|
| HTTP 401 | Token 是否有效、是否用了账号密码 |
| HTTP 400 且提到 v4_prompt | 模型与分角色载荷不匹配；换用下拉里的模型 |
| 参考图没生效 | 自检面板会明说「没有一个 Vibe 能用于当前模型」或参考图缺失 |
| 位置没生效 | 该角色「位置」是否设了；提示词里要有 `$角色名-…$` 才会被识别为分角色 |
| 第三方站点报 404 | 路径写法不一，客户端会依次试「地址 + /ai/generate-image」与裸地址，两个都失败才报错 |

## 第 3 步：SD WebUI（A1111 / Forge）

### 前置

WebUI 必须带 `--api` 启动，否则所有 `/sdapi/v1/*` 都 404。

### 配置

**SD WebUI** 页：地址 `http://127.0.0.1:7860` → 点「测试并读取模型列表」→
选模型、采样器、VAE（下拉内容来自服务端，比手填可靠）。

### 注意

**SD 渠道没有参考图机制，这是上游的行为，不是移植缺口。**
上游的 SD 路径只有 ADetailer 面部重绘；参考图是 ComfyUI 的 IP-Adapter 节点能力。
需要参考图请用 ComfyUI 或 NovelAI。自检面板也会这么提示。

## 第 4 步：Banana / Grok

**Banana / Grok** 页：地址、API Key、模型、尺寸。
设置页会**实时显示**当前会请求哪个端点，以及带参考图时会改请求哪个端点——
先核对这两个地址，再点生成。

配置界面里可以切「参考图发送形态」（multipart / JSON）。默认 multipart 是上游做法；
部分中转站只认 JSON 形式，切换即可。

**Banana 不支持负面提示词与种子。** 负向词不会发给服务端，生成参数里的种子记为「不适用」。

## 第 5 步：正文自动配图链路

前四步是单张出图。正文配图还多两个环节：**LLM 生成提示词** 与 **图片归档**。

打开「总览 → 启用正文配图」，并在「提示词」页配好**转化器**（一个可用的 LLM 接口）。

### 验证点

1. 发一条消息，看回复后是否自动出图。
2. **一张图**应插在正文对应行下方（按锚点匹配），不是全部堆在末尾。
3. 插图卡片标题行右侧是**图标操作**（悬停有说明）：查看大图 / 重新生成 / 修改提示词 / 换提示词。
   - 查看大图：按原始比例完整查看，可下载，Esc 关闭；点图片本身也一样。
   - 重新生成：按当前提示词再出一张（原来的「原样重生」）。
   - 修改提示词：展开编辑器，可改提示词与尺寸，确认后只重出这一张。
   - 换提示词：只让 LLM 重写提示词，**保留已出的图**。
4. 一条回复里多张图（模型输出多个 `<image>` 块）。

### 「正在生成」必须有反馈（防重复点击）

生图是**逐张**的、结果又在全部结束后才写回消息，所以每一段都必须自己报进度：

| 入口 | 点下去立刻能看到 |
|---|---|
| 卡片按钮「生成本回合插图」 | 按钮变「正在等待 LLM 写提示词…」并置灰；进入出图阶段变「正在逐张生成图片…」 |
| 单张「重新生成」/「修改提示词→重新生成本张」 | 那一张立刻变成「正在生成正文插图...」占位（该分支没有任何按钮）；失败会变回失败卡片并给出原因 |
| 「换提示词」 | 按钮变「正在等待 LLM 写提示词…」（不重出图） |
| 自动配图（总览 → 启用正文配图 + 自动模式） | 左侧**队列把手**显示「正在生成插图」并带脉冲点；展开队列可见「故事快照解析（等提示词）」与「故事快照生成（逐张出图，共 N 张）」两条 |

失败时看哪里：

| 现象 | 先查 |
|---|---|
| 点了没反应 | 队列抽屉里那一行的状态与 detail；被门禁拦下时会写明原因（例如「正文自动配图没有打开」） |
| 停在「正在生成…」不动 | 队列里那条 pending 的 detail（在等 LLM 还是第几张）；取消后重点 |
| 担心重复点 | 同一张图进入生成态后按钮就不存在了；整轮生成与重新解析在 pending 期间一律拒绝（见 `评估回合动作执行`）。不同图片各自独立，可以并行重生 |

### 失败时看哪里

| 现象 | 先查 |
|---|---|
| 没有任何图 | 「提示词预览」先确认转化器能用；自检会提示转化器未启用 |
| 图全堆在末尾 | 锚点行匹配不到正文，属正常回退；检查提示词里的锚点行是否照抄了正文 |
| 插图和行对不上 | 锚点行相似度阈值（40）；正文里那一行是否被改动过 |
| 只出一张 | 模型输出里只有一个 `<image>` 块；「每轮上限」是否设成了 1 |

## 第 6 步：角色管理（预设化的那四项）

「角色管理」页签下现在有五个子页：**角色卡 / 启用列表 / 通用列表 / 注入模板 / 生成**。
除「生成」会发一条 LLM 请求外，其余四页都是本地编辑，可以离线核对。

### 6.1 角色卡与角色包

1. 新建一张卡，填几个部位字段，提示词里写 `$名字-sfw-upperbody$` 到「提示词预览」验证替换。
2. 「导出全部」勾上「带图片音频」，得到一个 JSON；**清空角色后重新「导入角色包」**，
   卡片、服装与媒体都应回来（媒体会换新 id，卡片引用一并改写）。
3. 直接把上游 st-chatu8 导出的 `.json`（含 `characters` / `outfits` / `images`）拖进来：
   应能识别为 `chatu8` 格式，角色名做键也能吃；同时导入两次应当是**覆盖**而不是堆副本。

| 现象 | 先查 |
|---|---|
| 导入报「文件里没有 characters 表」 | 确认是角色包而不是整个设置导出 |
| 导入后没有图片 | 上游包里的图片是 `{id: dataURL}`；检查 `images` 字段是否还在 |
| 文本字段成了乱码 | 该文件 `_encrypted=true` 但 `_nameMap` 丢失，无法反解；让对方重新导出 |

### 6.2 启用列表

1. 把角色加入启用列表；「触发测试」里贴一段正文，应只列出名字出现过的角色。
2. 清空列表后看「渲染结果」：应显示「（暂无启用的角色）」。
3. 条目上绑定图片/音频后，`{{角色启用列表}}` 里应使用条目上的覆盖值。

### 6.3 通用列表与注入模板

1. 通用角色/通用服装加入条目后，`{{通用角色启用列表}}` / `{{通用服装启用列表}}` 的渲染结果应更新。
2. 注入模板里把某一行改成只含一个空字段（如 `年龄：{traits}` 而角色没有该值），
   该行应**整行消失**；若所有占位行都消失，整体应渲染成空串。
3. 切到「Tavern XML 格式」再看渲染结果，应变成 `<character …>` 形态。

### 6.4 一键生成角色特征

1. 「生成」页选目标卡：可以是**已有卡**，也可以选「＋ 新建角色卡」直接造一张
   （填个名字，留空就用模型给出的中文名）。新建的卡会**自动挂进当前启用列表**，
   否则它在提示词里不可见。
2. 写一句要求（名字＋身份＋外观要点），点「一键生成」。
3. 得到的是**可编辑的对照表**：每个字段都是输入框，新值在上、旧值（若有）带删除线在下，
   默认全选；改过的字段会标「已手工修改」。**改完再写回**，不必先保存再去「角色卡」页改。
   同时生成的 `<服装>` 块也能逐项改（中文名 / 英文名 / 上下半身与背面 / 全身 / 负面）。
4. 点「写入角色卡」（新建模式下是「新建角色卡「名字」并写入」）后回「角色卡」页确认字段已落。
5. 模型跑偏（没给 `<人物>` 块）时，界面应给出**空回分类**并自动摊开原始回复。

#### 提示词为什么要带破甲

默认消息序列逐字收录了「人物生成」预设里角色卡那一组的全部启用块：

    初始化（破甲对话）→ 故事框架（开/合）→ 增强定义 → user人设
    → 角色设计（`<人物>` 格式）→ 服装风格（`<服装>` 格式）→ 讨论模式（默认停用）

**只发格式规格时，模型面对 NSFW 字段最省事的做法是回一句拒绝** —— 现象就是「经常空回」。
破甲对话（`初始化`）的作用是把模型带进「边界内可以写得具体」的状态，所以它在默认序列里是第一条。
顺序即语义：`system / user / assistant` 交替出现，别把它们并成一条。

「讨论模式」默认停用：它要求先输出 `<talk>` 讨论再输出 `<content>`，而本应用是单次调用，
思考型模型容易把输出额度耗在讨论上、给不出 `<人物>` 块。想让模型先讨论再设计时再打开。

#### 失败时看哪里

| 现象 | 先查 |
|---|---|
| 报「没有可用的模型接口」 | 角色 AI 覆盖 → 文生图 LLM 预设 → 主 API 三级都空；去「设置 → API」配一个 |
| 提示词内容被截断 | 「最大输出」调大（默认 12288；破甲对话本身也占输出） |
| 提示里出现 `finishReason=SAFETY` | 模型/中转拒绝了内容：换一个未开启审查的模型，或先停用 NSFW 规格只生成 SFW 字段 |
| 提示里出现 `finishReason=MAX_TOKENS` | 额度耗尽：调大「最大输出」，或停用「讨论模式」 |
| 提示「只返回了 reasoning_content」 | 中转把思考与正文分流：换中转，或关掉该模型的思考模式 |
| 提示 `prompt_tokens=0` | 请求没到模型，在中转层就被拦了：调提示词无用，先排查中转 |
| 解析不到字段 | 点「查看模型原始回复」；多半是模型没按 `<人物>` 格式输出 |
| 某些字段没写回 | 生成值为空的字段**一律不覆盖**，这是有意的（防审查导致的漏字段抹掉手写内容） |

「空回重试次数」默认 1：解析不到 `<人物>` 块会自动重问一次，用来区分「偶发」与「稳定拒绝」。

### 6.5 与上游的差异（有意为之，不要当缺口）

- 上游的**翻译**按钮与**逐字段 token 统计**未移植：前者需要额外的翻译提示词，
  后者上游走酒馆的 `/api/tokenizers/openai/count`，本应用没有对应的分词端点。
- 上游每个页签各自带一套「预设导入导出」；本应用只在角色卡页做角色包导入导出，
  三类列表与注入模板随设置一起保存/随角色包内的启用名单一起走。
- 上游的「可视化选择」（网格 + 分页 + 批量删除）在本应用改成列表内的「批量」模式：
  勾选后删除所选，不另开弹窗。
- 上游的服装是**独立预设表**（`outfitPresets` + 角色上存 id 数组），本应用的服装
  挂在角色卡内（导入导出时才按上游形状摊平），因此没有独立的「服装管理」页签。

## 第 7 步：图片缓存（按提示词归档的图廊）

「图片生成 → 图片缓存」页。写入侧每次出图都在做（只要「总览 → 图片缓存」开着），
这里验的是**读得出来**：

1. 出几张图，打开这一页：应能看到缩略图、提示词、尺寸、大小与时间（新的在最前）。
2. 点缩略图放大（Esc 关闭，可左右切换、可下载）；悬停右上角可**只删这一张**。
3. 「刷新缓存」重新读一次；「清空缓存」后应显示「缓存里还没有图片」而不是一片空白。
4. 「设置 → 文生图 → 图片缓存」页显示的是同一份容量（进入即自动读取）。

| 现象 | 先查 |
|---|---|
| 有张数、没有图 | 以前只会显示计数：读取侧原先没有入口（已修）。若仍为空，看控制台有没有 `image-cache-write-failed` |
| 一张都没有 | 「总览 → 图片缓存」开关是否打开；「保留天数」是否为 0（大于 0 会在打开工作台时清理过期条目） |
| 图裂开 | 记录没有字节（清理中断或旧版本残留）：`列出缓存图片` 会跳过这类记录，清空后重新生成即可 |
| 正文里的图也不显示 | 那是**相册**（另一套存储）：`asset:<id>` 只有在字节可解析时才能显示，见第 5 步 |

## 已知的、刻意保留的行为

这些看起来像 bug，其实是照搬上游。**不要顺手"修"**（测试里已固化）：

- `小学生` → `🏬生`：词汇替换的子串遮蔽
- 提示词里的尺寸 `WxH` **后跟逗号时不匹配**
- 全角归一化只处理 `,`，不处理 `;` 与 `:`
- 角色卡的 `fullBody*` 字段承载的是**下半身**，不是全身（界面文案已写「下半身」）
- 打开「参考强度归一化」时，**4.5 full/curated 反而交给 NAI 自己归一化**
- 角色参考的「保真度」**不上行**，发送的是 `1 - 强度`（界面上没有暴露该字段）
- Banana 的 `imagen*` 模型**不发 `size`**

## 上游没有的能力（不是缺口）

- SD 渠道的参考图（只有 ComfyUI 的 IP-Adapter 节点）
- 视频（本轮范围外，用户明确暂不需要）

## 若某个渠道通不了

把**自检面板的输出**、浏览器控制台的报错、以及服务端的响应体一起给我。
有这三样基本能一次定位，不必反复试。
